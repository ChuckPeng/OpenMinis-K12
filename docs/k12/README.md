# OpenMinis-K12 工程文档

产品设计主本是 r16 设计稿（2026-10-29，M0 设计基线）。本文目录是**此后的工程事实来源**：接口、数据、模块边界、验收编号与未决项以这里为准。设计稿与本文冲突时，先改本文并记入「待定」，不在代码里悄悄选边。

编码仍须仓库所有者明确同意后才开始。本目录不修改上游应用代码、构建文件或 `docs/specs/`。

## 怎么读

1. 产品范围与已拍板决定：`decisions/`。
2. 系统怎么拼起来：`architecture.md`。
3. 做哪个模块：`modules/`，再对 `api/` 与 `data-model.md`。
4. 改上游文件之前：`upstream-patches.md` 与 `conventions.md`。
5. 什么算做完：各模块文末的验收编号；门槛与试点见 `test-plan.md`。
6. 先做哪一块：`roadmap.md`。

显示名 **伴学 Minis**，`applicationId` **com.openminis.k12**。服务端产品名 **OpenMinis-K12 服务端**，技术标识 `openminis-k12-server`，目录 `server/`。协议保持 GPL-3；服务端许可证见 T-08。

## 明确不写入本文档与仓库的内容

真实姓名、学校、班级、成绩、某一家庭的教材版本、设备型号、IP、主机名。学生档案只在平板本机，由家长编辑。服务端只存 `child_id`、家长自定标签、学段与配置。
