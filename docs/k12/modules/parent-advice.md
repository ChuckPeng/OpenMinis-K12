# 亲子成长建议

## 职责

在报告之外，给家长一段可执行的陪伴建议：一条观察、2–3 条可做可说、一条先别做、可选的短活动。从可审阅的条目库里选，模型只改写，不自由发挥。不是诊断。

只经企微卡片与网页报告页送达。设备接口不返回。这是「孩子能看到家长看到的数字」的唯一例外。孩子端清单写明家长会收到陪伴建议，但不显示内容。

## 分期

M5f。开始前须 M5e 已用，且至少有 4 周真实数据。未到该里程碑不实现生成。

## 公开接口

无设备 API。管理页：浏览、停用、新增家庭条目、导入导出 YAML。

报告字段 `parent_advice_json`：每条有 `entry_id`、`principle`、`metric_refs`。网页按钮：有用 / 没用 / 已经在做。

## 数据

条目库 YAML：随二进制 `go:embed`，数据目录可覆盖。字段：`id`、`stages`、`kind`（observe/do/say/avoid/activity）、`trigger`、`text`、`principle`、`source_note`、`priority`、`version`、`reviewed_by`、`reviewed_at`。

`advice_feedback` 保留 1 年。反馈只改排序，不改任何指标。

输入信号只用聚合数字与枚举：努力与坚持、受挫（含 `attempt.outcome = abandoned`）、进步、情绪级别与可选心情打卡、作息、作业负荷、未来 14 天考试、学段。不含昵称、真名、题目、聊天、图片。每个孩子只用自己的数据。

## 依赖

报告模块的指标、模型网关、告警级别、v1.2 起的考试条目（没有钉钉时考试只来自网页手填）。

## 状态与流程

1. 按信号匹配 `trigger`，过滤学段与家长关注方向。
2. 去掉 4 周内已出现的，以及被标「没用」而降权的。
3. 按 `priority` × 反馈权重排序，每类取若干，候选不超过 12。
4. 模型只能从候选里选。校验失败重试一次，再失败用模板。
5. 本期「紧急」≥ 阈值或「关注」达到阈值：整段换成固定关怀模板，不经模型，且不给学业加码建议。即时告警照常。阈值见 T-11。
6. 心情打卡勾选「想聊聊」：下一份报告的第一条固定为邀请家长倾听，不展示打卡原文以外的信息。

日简报仅在显著信号时出一句，每周最多 2 次（T-11）。周报、月报、学期报告在开启时总是给出完整结构。随时查看可显示，不写反馈调权。

禁用词：病名或心理标签、责备、兄弟姐妹或与他人比较、排名。

## 错误处理

| 情况 | 行为 |
| --- | --- |
| 覆盖 YAML 校验失败 | 沿用上一版，并记日志 |
| 模型不可用 | 报告照常，建议标「由条目库模板生成」（P8） |
| 候选为空 | 设计未写（T-51）。不要临时编造条目 |

## 配置

每孩子：开关、深度（简要/标准/详细）、关注方向、跟随报告的文字生成方式、心情打卡、关怀阈值、学段覆盖。建议默认见 T-11。
