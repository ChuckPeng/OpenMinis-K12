# 拍题分层辅导

## 职责

拍题后先确认题干，再按壳层状态机分层提示。完整解单独生成，未到揭晓不展示。教法在技能 `study-companion-core` 与学科技能里。壳层不把揭晓交给模型自己判断。

## 分期

| 批次 | 范围 |
| --- | --- |
| v1 M2 | 题干确认、提示链、三档变式、卡住换讲法、拍草稿、本机 PIN/TOTP、泄题检查、评测 v0、本机事件 |
| v1 M5b | 「申请看答案」从 PIN 弹窗改为远程申请。状态机不变 |
| 不做 | 高中教法；本地 OCR（v1 把图交给多模态模型） |

## 公开接口

| 接口 | 方向 |
| --- | --- |
| 揭晓状态机 | 壳层内部。输出当前允许的层级 |
| `buildSystemPrompt` 委托（H-09） | 只附加「当前层级与禁止事项」，不在 `ChatViewModel` 里写规则 |
| `read_image`（H-10） | 拍题与拍草稿 |
| 计算工具 | 数学的数值、方程、化简、因式分解由工具得出。模型只讲思路。选型 T-32 |
| 解锁模块 | 到达可申请状态后调用。M2 只调本机 PIN/TOTP |

## 数据

本机聊天仍在上游会话库。本模块写入 `session_*`、`active_span`、`attempt`、`hint_used`、`answer_reveal`。不上报题目原文。题干确认与验算是否单独记事件：T-48。

## 依赖

课程目录（学段、教材字段）、家长管控（PIN、作业/考试标记）、内容安全（注入与预筛）、M5b 起的解锁与同步。

## 状态与流程

设计 §19.1 的状态（层名冲突见 T-03，进入条件见 T-04）：

| 状态 | 进入 | 允许输出 |
| --- | --- | --- |
| 题目确认 | 新题拍照或输入 | 只显示识别出的题干。可改字或重拍。低年级可朗读。低置信度要求重拍 |
| L0 引导 | 孩子确认题干 | 复述题意、问思路。不给步骤与答案 |
| L1 提示 | 求助或答错 | 知识点或第一步方向 |
| L2 分步 | 再次求助 | 关键步骤，留下最后一步 |
| L3 揭晓 | 见 T-04 | 完整解答，并写揭晓日志 |

未到 L3：输出若含与参考答案一致的最终数值、选项或完整算式，则拦截并要求按当前层重写。再失败则显示固定提示语（原文 T-36）。

已确认的产品规则（§4.5.1）仍然有效，直到 T-04 改写状态表：

| 情形 | 默认 |
| --- | --- |
| 未作答或未走完提示链 | 只给下一级。不可放宽 |
| 已作答且走完提示链仍不会 | 可申请。家长解锁后单题一次 |
| 作业/考试模式 | 无解锁不出完整解 |
| 已提交后的复盘 | 默认可看完整解与讲评 |
| 解锁粒度 | 单题一次。家长可改为限时，默认 15 分钟，离开会话恢复锁 |

每次揭晓记录：题目缩略（本机）、走过的层数、方式（PIN / 解锁码 / TOTP / 远程）。孩子看不到解锁码。

理科：两遍推导或工具验算不一致、题干不确定、超纲、开放题无标准答案时，说不确定并给出「问老师」。该题记「待核」，出现在日简报，不计入错题与掌握度（T-35）。超纲要标明。

辅导结束默认 3 道变式：基础、同级、稍难。同一题多次卡住则换讲法。

## 错误处理

| 情况 | 行为 |
| --- | --- |
| 识别失败或孩子否认题干 | 停留在题目确认 |
| 泄题检查失败 | 重写；仍失败用固定提示语 |
| 工具不可用或结果不一致 | 「不确定 / 问老师」，不展示不一致的数字 |
| 越狱话术 | 不改变状态机 |

## 配置

揭晓策略、学段由服务端下发（家长可按学段改，红线不可放宽）。高年级「走完提示链自动揭晓」是策略项，默认关。
