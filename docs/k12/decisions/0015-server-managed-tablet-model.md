# ADR-0015 平板讲题模型由家长在服务器配置并下发

- 状态：已接受
- 日期：2026-11-03
- 关系：部分取代 ADR-0006。ADR-0006 里「不改 `provider/` 协议、不设默认厂商、不校验 Base URL 是否属于某厂商、不做金额预算、服务端小模型 Key 不下发」仍然有效。被取代的是「家长只在平板上填写讲题模型 Key」这一条。

## 背景

平板讲题仍走上游 Minis 模型层。家长如果必须在每台平板上填写供应商、Base URL 和 API Key，换机和误改都麻烦。把全部模型流量改由服务器代理被否决：对话和图片会经过家庭服务器，范围和故障面都变大。

## 决定

家长在管理页配置一次平板讲题模型：供应商类型、Base URL、API Key、模型名，以及上游支持单独视觉模型时的视觉模型名。范围是家庭级。v1 只有一个家庭，数据模型里 `device_config` 不能放密钥，因此不做按孩子覆盖。

服务器用主密钥 AES-256-GCM 保存 API Key。管理接口只写不回显，只显示是否已设置和上次修改时间。配置带单调递增的版本。日志和审计不记录密钥。

心跳只带回这个版本，不带回密钥。版本变化时，已配对的平板向专用设备接口拉取完整配置。未配对、待确认或已吊销的设备得到 401 或 403。每次下发写审计：设备 id、版本、时间，不含密钥。

平板把下发结果放进 Android Keystore 支持的加密存储，再通过现有的供应商配置接口写到上游模型层。生效期间，本机供应商与 Key 页面改为只读，并标明由服务器管理。服务器清除配置后，平板回到下发之前的本机配置。解绑或重置会删掉已下发的密钥。平板不记录密钥。

不改 `provider/` 的协议实现。不选默认厂商。Base URL 只检查是不是合法的 http 或 https URL。不做金额预算。服务器自己的抽取和报告模型仍只留在服务器，不走这条下发。

## 后果

讲题流量仍由平板直接访问家长填写的上游地址。服务器只保存并下发配置。讲题质量仍取决于家长所选模型和技能。
